| # | 가정 | 판정 | 근거 |

| A5 | robots.txt가 수집을 막지 않는다 | ⚠️ 조건부 PASS | 게시판 경로 허용, `/_attach/` 차단 → §3 참조 |

**A2 확정 셀렉터**

```
목록  a[href*="mode=view"]  → 부모 <tr>/<li>에서 날짜
본문  div.b-content-box     ← 확정. "가장 긴 div" 폴백은 제거함
제목  p.b-title
등록일 div.b-etc-box
첨부  div.b-file-box a
```

스켈레톤의 "가장 긴 div" 폴백은 실측에서 본교 페이지의 **네비게이션 메뉴(1374자)**를 본문으로 잡았다. 그대로 뒀다면 LLM이 대학 소개 메뉴를 읽고 마감일을 지어냈을 것이다 — HANDOFF가 경고한 최악의 실패 모드. 폴백 없이 셀렉터를 고정했다.

## 3. robots.txt — 경로별로 결론이 다르다

3개 도메인 모두 동일:

```
User-agent: *
Disallow: /_attach/
Disallow: /_custom/
Disallow: /_res/
```

| 대상 | 실제 URL | robots.txt |
|---|---|---|
| 게시판 목록·상세 | `/dormitory/board/*.do?mode=view` | ✅ 허용 |
| **본문 이미지** | `/_attach/cuk/editor-image/2026/07/*.png` | ❌ **차단** |
| **첨부파일 다운로드** | `{board}.do?mode=download&articleNo=&attachNo=` | ✅ 허용 |

이미지 OCR/비전 판독은 차단 경로 접근이라 HANDOFF §13·§5(A5)에 따라 **임의 진행 불가**.
반면 HWP/PDF 첨부 다운로드는 게시판 경로의 쿼리라 robots.txt에 걸리지 않는다.

단, 첨부 커버리지도 부분적이다 — `dorm_f_general`은 표본 8건 전부 첨부 0개, `dorm_f_inout`은 8건 중 4건만 첨부가 있다.

## 4. 의뢰인 결정 대기 항목 (HANDOFF §14)

M1은 여기서 멈춘다. 아래 결정 없이 M2로 넘어가지 않는다.

1. **이미지 공지를 어떻게 다룰 것인가** — 제목만으로 알림(즉시 가능) / 첨부 파싱 2차 승격 / 학교에 문의 후 이미지 판독
2. **robots.txt `/_attach/` 차단** — 이미지 판독이 필요하다면 의뢰인이 리스크를 인지하고 명시 승인해야 함
3. 마감일 추출 불가 시 **D-7/3/1 리마인더 기능의 축소 범위**

## 5. 핸드오프 §1 전제 수정 — 기숙사 공지는 본교에도 일부 올라온다

HANDOFF §1은 "기숙사 공지는 본교 공지사항에 **전혀** 게시되지 않는다"고 단정하지만, 실측 결과 **일부는 게시된다.**

본교 공지사항 최근 60건 중 기숙사 관련 6건:

```
2026-07-31  [기숙사운영팀] 2026-2학기 프란치스코관 추가 모집 공고 - 내국인(여학생)
2026-07-31  [기숙사운영팀] 2026학년도 2학기 스테파노관 B동 대학원생 추가 모집(내국인)
2026-07-31  [기숙사운영팀] 2026학년도 2학기 안드레아관 대학원생 추가 모집 공고(내국인)
2026-07-22  [기숙사운영팀] 2026-2학기 기숙사(K관, A관) 내국인 남자 학부생(재학생) 추가 모집 공고
2026-07-21  [기숙사운영팀] 2026-2학기 기숙사 야간생활조교 모집 공고 (선발 완료)
2026-07-15  [기숙사운영팀] 2026-2학기 기숙사 (A,K관) 대학원생 합격자 발표(내국인)
```

동일 공지가 게시판별로 다른 `article_no`를 갖는다. 예: 프란치스코관 추가 모집이 본교 `#274354`, `dorm_f_inout` `#274353`이며 말머리만 `[기숙사운영팀]` / `[F관]`으로 다르다.

**그래도 프로젝트 전제는 유지된다.** 재게시되는 건 모집·발표 계열 일부이고, 정기퇴사 안내·층 분류 현황·합격자 발표 상당수는 기숙사 게시판에만 있다. 기숙사 게시판 수집은 여전히 필요하다.

**함의**

- §11.3 재게시 dedup이 이론적 대비가 아니라 **상시 발동하는 경로**다. 게시판 순회 순서상 본교 버전이 먼저 저장되고 기숙사 버전이 중복으로 걸린다
- 재게시 판정이 잘못되면 기숙사 모집 공고 알림이 통째로 사라진다. `collect_board`가 저장 후 판정하던 버그가 정확히 이 사고를 냈고, `tests/test_core.py::CrossPostDetection`이 회귀를 막는다

**미확인:** 60건 창이 약 6주만 덮으므로 그 이전 공고(예: 2026-06-23 학부생 모집공고)의 재게시 여부는 판단하지 않았다.
